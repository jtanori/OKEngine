### 0.3 Five-Stage Architectural Request Flow (Authentication vs. Authorization vs. Trusted Scope)

Every OKEng endpoint is governed by five distinct stages so that **legitimate anonymous public accessibility at Stage 2** never permits **client-controlled scope or privilege elevation at Stage 3 or Stage 4**:

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ STAGE 1: REQUEST BOUNDARY                                                              │
│  • Route-Specific Payload Byte Cap (16KB Auth │ 64KB Default │ 256KB Chat │ 10MB File) │
│  • Layer 1 Structural Schema Validation (`.strict()` unknown-key rejection)            │
│  • Pre-Auth Distributed Rate Limit (Trusted Proxy IP + Route Tier)                     │
├───────────────────────────────────────────┬────────────────────────────────────────────┘
                                            ▼
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ STAGE 2: VERIFIED IDENTITY                                                             │
│  • Domain A: Server-Verified `__Host-okeng_session` Cookie + Session-Bound CSRF Token  │
│  • Domain B: Cryptographically Verified `HS256` Host Assertion (`iss`,`aud`,`sub`,`jti`)│
│  • Domain C: Signed `embedSessionToken` OR Explicit `anonymous` Identity               │
│  • Invariant: Client-supplied headers/body fields NEVER override the session resolver  │
├───────────────────────────────────────────┬────────────────────────────────────────────┘
                                            ▼
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ STAGE 3: AUTHORIZATION                                                                 │
│  • Domain A: 5-Link Guard (Active User → Active Workspace → Active Membership/Grant    │
│    → Granular Permission → Composite `(workspaceId, resourceId)` Ownership)            │
│  • Domain B/C: Active Embed Installation + Clearance Tier Mapping + Non-Revoked Epoch  │
├───────────────────────────────────────────┬────────────────────────────────────────────┘
                                            ▼
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ STAGE 4: SERVER-RESOLVED SCOPE                                                         │
│  • Server loads allowed `collections`, `documents`, and `embeds` strictly from         │
│    trusted persistence (`repositories` / PostgreSQL RLS)                               │
│  • Public Access != Untrusted Scope: Anonymous public embeds (`EMB-PUBLIC-HOME`) and   │
│    public share links (`is_public_document = true`) are accessible without login at    │
│    Stage 2, but remain strictly constrained at Stage 4 to server-resolved              │
│    `visibility = 'everyone'` records—never client-supplied arrays or role claims       │
├───────────────────────────────────────────┬────────────────────────────────────────────┘
                                            ▼
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ STAGE 5: PROTECTED OPERATION                                                           │
│  • Scoped BM25 / Deterministic Retrieval & Citation Filtering                          │
│  • Atomic Gemini Token Budget Reservation & AbortSignal-Bound Generation               │
│  • Repository Mutation, Two-Phase Storage Write, or Scoped Cache Invalidation          │
└────────────────────────────────────────────────────────────────────────────────────────┘
```
