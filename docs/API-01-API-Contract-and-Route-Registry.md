## 1. Ordered 8-Stage Express Request Pipeline

Every incoming HTTP request traverses the following deterministic 8-stage pipeline so invalid origins, oversized payloads, rate-limit violations, and malformed schemas are rejected **before** authentication, database queries, or paid Gemini API calls execute:

1. **Stage 1 — Request Correlation & Security Headers**: Assigns `req.requestId` (`req_<ulid>`), echoes `X-Request-Id`, and sets `Content-Security-Policy`, `Strict-Transport-Security`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, and `X-Frame-Options` (relaxed only on `/embed/*` routes per workspace host allowlist).
2. **Stage 2 — Origin / CORS Policy & Method Guard**: Rejects any state-changing operation attempted via `GET`, `HEAD`, or `OPTIONS`. Enforces exact-origin matching against `OKENG_ALLOWED_ORIGINS` for Domain A routes.
3. **Stage 3 — Route-Specific Payload Size Cap**: Replaces the legacy global `express.json({ limit: '10mb' })` (`server.ts` line 71) with tiered body parsers:
   - `16 KB`: Auth & session routes (`/api/auth/*`, `/api/embed/session*`, `/api/embed/verify`)
   - `64 KB`: Default JSON API parser for workspace, collection, embed, and governance metadata routes
   - `256 KB`: Chat, document markdown edit, and answer export/save routes (`/api/chat*`, `/api/workspaces/:workspaceId/documents*`)
   - `10 MB`: Strictly restricted to authenticated file upload (`POST /api/workspaces/:workspaceId/files`)
4. **Stage 4 — Pre-Auth Distributed Rate Limiter**: Evaluates IP and route-tier sliding windows via `RateLimiterAdapter` (`OPS-01 §2`).
5. **Stage 5 — Layer 1 Structural Schema Validation**: Validates `req.params`, `req.query`, and `req.body` against strict route schemas with unknown-key rejection (`.strict()`), explicit string/array bounds, and zero implicit type coercion.
6. **Stage 6 — Domain Authentication & CSRF Verification**: Verifies Domain A (`__Host-okeng_session` cookie + `X-CSRF-Token`), Domain B (signed `HS256` host assertion), or Domain C (`Bearer <embedSessionToken>`).
7. **Stage 7 — Layer 2 Semantic 5-Link Authorization & Ownership Verification**: Enforces workspace membership, granular permission, composite `(workspaceId, resourceId)` ownership, and pre-retrieval `AuthorizationScope` filtering.
8. **Stage 8 — Atomic Workspace Quota & Token Budget Reservation**: Reserves Gemini token budget (`reserveTokens`) and binds `req.on('close')` `AbortController` cancellation prior to upstream model invocation.

## 2. Four-Layer Validation Architecture

| Layer | Name | Responsibility | Error Code & Status Contract |
| :--- | :--- | :--- | :--- |
| **Layer 1** | **Structural Validation** | Separate strict schemas for `params`, `query`, and `body`. Rejects unknown fields (`SCHEMA_UNKNOWN_FIELD`), enforces types, length caps, enum values, and array bounds without coercion. Never echoes rejected raw values or secrets. | `400 Bad Request` (`{ error: "VALIDATION_ERROR", code, field, requestId }`) |
| **Layer 2** | **Semantic Validation & Authorization** | Verifies resource existence, active membership, granular permission, composite parent-child relationship (`(workspaceId, collectionId, documentId)`), `DATA-003` state transitions, and last-owner protection. | `401` / `403` / `404` (`{ error: "RESOURCE_NOT_FOUND", requestId }` on cross-tenant IDs) |
| **Layer 3** | **Contextual Output Safety** | Deterministic AST Markdown sanitization (`src/content/sanitizer`), safe URL protocol validation (`https:`, `mailto:`, `/`), and `Content-Disposition: attachment` on file downloads. | Strips or rejects unsafe constructs (`400 XSS_PAYLOAD_REJECTED`) |
| **Layer 4** | **Protocol & Resource Safety** | Enforces payload byte caps, multipart file count (`maxFiles: 1`), MIME verification, max retrieved chunks (`8`), max output tokens (`1024`), upstream timeout (`15s`), and stream disconnect cancellation. | `413 Payload Too Large` / `429 Too Many Requests` / `504 Gateway Timeout` |

## 4. Specific Route Lifecycle & Edge-Case Contracts

1. **Workspace & Membership Mutations (`RTE-MEM-01..04`)**:
   - Inviting an existing member (`UNIQUE (workspace_id, user_id)`) returns `409 MEMBERSHIP_ALREADY_EXISTS`.
   - Both the application layer (`MembershipRepository`) and PostgreSQL trigger `trg_protect_last_workspace_owner` (`20261009000003` Section 3) reject any attempt to delete, revoke, or demote the last `ACTIVE` `WORKSPACE_OWNER` of a workspace (`409 LAST_WORKSPACE_OWNER_PROTECTED`).
2. **Document Ingestion & Asynchronous Lifecycle (`RTE-FILE-01`, `RTE-DOC-03..04`)**:
   - Follows the `DATA-003` state machine (`uploading` → `processing` → `indexing` → `ready` | `failed` | `deleted`).
   - Deleting a document (`RTE-DOC-04`) while an indexing job is in flight increments the document's `version_number` and sets `deleted_at = NOW()`. The indexing worker checks `deleted_at IS NULL` inside a transaction before committing chunks, discarding stale chunks if the document was deleted mid-flight.
3. **Embed Invalidation (`RTE-EMB-02..04`)**:
   - Disabling an embed (`status = 'draft'`), deleting an embed, or removing a collection from `knowledgeScope.collectionIds` alters `computeEmbedAuthorizationVersion()`. Any existing Domain C `embedSessionToken` presenting a stale `authorizationVersion` is immediately re-evaluated or rejected (`401 EMBED_SESSION_REVOKED`) on the next request.
4. **Share Snapshot Integrity (`RTE-ACT-03`)**:
   - The server **never** trusts `req.body.isPublicDocument`. Instead, `ShareRepository.createSnapshot` queries `public.collections` for `(workspaceId, collectionId)` and sets `is_public_document = (collection.visibility === 'everyone')`. Snapshots of `members` or `admins` collections require Domain A `content.read` authorization on `GET /api/embed/share/:shareId` and default to a 7-day expiration (`expires_at`).
5. **Streaming Error & Disconnect Contract (`RTE-AI-01`)**:
   - Authentication, 5-Link authorization, schema validation, and token budget reservation (`Stage 1` through `Stage 8`) execute **before** `res.setHeader('Content-Type', 'text/event-stream')` and `res.flushHeaders()` are called, so errors return standard HTTP `400`/`401`/`403`/`404`/`429`/`503` JSON payloads.
   - Once streaming begins, `req.on('close')` triggers `abortController.abort()`, immediately cancelling any active `ai.models.generateContentStream` call and reconciling only the tokens streamed prior to disconnect.
